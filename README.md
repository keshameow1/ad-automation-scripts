# AD Account Cleanup Automation

Набор PowerShell-скриптов для автоматизации жизненного цикла профилей уволенных
сотрудников на файловом/терминальном сервере: обнаружение отключённых в Active
Directory учётных записей, изолированное хранение их локальных профилей и
плановая очистка данных с истёкшим сроком хранения.

## Проблема

На сервере с терминальными/локальными профилями пользователей со временем
накапливаются папки в `C:\Users`, принадлежащие уволенным сотрудникам:
учётная запись в AD уже отключена или удалена, а данные профиля (включая
почтовые архивы Thunderbird) продолжают занимать место на диске и
представляют риск с точки зрения хранения персональных данных.

Раньше эта проверка выполнялась вручную. Задача — превратить её в
еженедельный автоматический процесс без участия администратора.

## Как это работает

Три скрипта выполняются последовательно по расписанию (каждое воскресенье
ночью) через Планировщик заданий Windows:

| # | Скрипт | Время | Что делает |
|---|--------|-------|------------|
| 1 | `move_disabled_accounts.ps1` | 03:00 | Сверяет папки в `C:\Users` со статусом учётной записи в AD. Если аккаунт отключён (`ACCOUNTCONTROL`) или не найден в AD — переносит папку профиля в `C:\Users\_Уволенные` и проставляет метку даты переноса. |
| 2 | `remove_thunderbird_profiles.ps1` | 03:30 | Проходит по всем папкам в `_Уволенные` и удаляет `AppData\Roaming\Thunderbird\Profiles` — самые тяжёлые и наименее нужные после увольнения данные удаляются сразу, а не через 90 дней. |
| 3 | `cleanup_old_disabled_accounts.ps1` | 04:00 | Удаляет из `_Уволенные` те профили, что находятся там дольше `DaysThreshold` (по умолчанию 90) дней — читает дату переноса из метки, оставленной первым скриптом. |

Подробная схема регистрации задач в Планировщике — см.
[`docs/scheduled-tasks-setup.md`](docs/scheduled-tasks-setup.md).

## Скрипты

### `move_disabled_accounts.ps1`

Сканирует `C:\Users`, для каждой папки (кроме служебных из `$exclude`) ищет
пользователя в AD по `sAMAccountName`, равному имени папки, через
`DirectoryServices.DirectorySearcher`. Если пользователь не найден или его
учётная запись отключена (бит `ACCOUNTDISABLE` в `userAccountControl`) —
папка переносится в `_Уволенные`, туда же кладётся файл `_moved_date.txt` с
датой переноса (используется скриптом очистки для расчёта возраста).

Работает без интерактивных вопросов — подходит для запуска по расписанию.
Все действия и найденные записи логируются в
`move_disabled_accounts.log` в папке скрипта.

### `remove_thunderbird_profiles.ps1`

Проходит по всем подпапкам `_Уволенные`, проверяет наличие
`AppData\Roaming\Thunderbird\Profiles` и удаляет её без подтверждения.
Логирует результат в `remove_thunderbird_profiles.log`.

### `cleanup_old_disabled_accounts.ps1`

Принимает параметр `-DaysThreshold` (по умолчанию 90). Для каждой папки в
`_Уволенные` читает дату переноса из `_moved_date.txt` (если метки нет —
берёт `CreationTime` папки как приближение) и удаляет папку целиком, если
она находится там дольше порога. Логирует в `cleanup_old_disabled_accounts.log`.

## Требования

- PowerShell 5.1+ (встроен в Windows Server / Windows 10+).
- Права на чтение объектов пользователей в Active Directory.
- Права на чтение/запись/удаление в `C:\Users` (для запуска по расписанию —
  учётная запись `СИСТЕМА` с `RunLevel Highest`, см. `docs/scheduled-tasks-setup.md`).

## Настройка под свою инфраструктуру

Перед использованием отредактируйте в скриптах:

- `$profilePath` — путь к папке с профилями пользователей (по умолчанию `C:\Users`).
- `$exclude` — список системных/служебных папок, которые не нужно проверять
  (встроенные учётки Windows, сервисные аккаунты и т. п.).
- `$deletedFolderName` — имя папки-«карантина» для уволенных.
- `$DaysThreshold` в `cleanup_old_disabled_accounts.ps1` — срок хранения
  профиля перед окончательным удалением.

## Безопасность и ограничения

- Удаление в `cleanup_old_disabled_accounts.ps1` и
  `remove_thunderbird_profiles.ps1` — безвозвратное (`Remove-Item -Force`,
  без корзины). Перед боевым использованием рекомендуется прогнать на
  тестовой папке.
- Скрипты рассчитаны на среду с классическим on-premise Active Directory
  (`System.DirectoryServices`); для Azure AD / Entra ID потребуется другой
  механизм проверки статуса учётной записи.
